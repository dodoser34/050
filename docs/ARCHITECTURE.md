# Как устроена «Среда»

«Среда» — компактное приложение на FastAPI с прямыми SQL-запросами к SQLite. Основная единица кода — пользовательский сценарий: его HTTP-обработчики и модели входных данных находятся в одном файле `backend/app/features/`. Чтобы разобраться с откликом на проект, достаточно начать с `features/projects.py`.

## Найти нужный сценарий

| Файл относительно `backend/app/` | Ответственность |
|---|---|
| `features/auth.py` | Регистрация, вход, выход, демо-вход; модели `RegisterIn`, `LoginIn` |
| `features/account.py` | Кабинет и анкета специалиста; `ProfileIn`, портфолио и опыт |
| `features/people.py` | Каталог специалистов, избранное и приглашения; `InviteIn` |
| `features/projects.py` | Каталог, создание, лайки и отклики; `ProjectIn`, `ApplyIn` |
| `features/home.py` | Данные главной страницы |
| `features/search.py` | Общий поиск |
| `features/admin.py` | Модерация, пользователи, выбор героев главной; `ModerateIn`, `FeaturedIn` |

Модели проверки находятся перед обработчиками своего сценария. Общего каталога схем нет: правила анкеты не нужно искать среди правил регистрации или модерации.

## Общий код

`main.py` собирает приложение, подключает обработчики ошибок, сценарии и статику. `web/routing.py` задаёт порядок подключения; `web/pages.py` отдаёт HTML; `web/dependencies.py` определяет пользователя и права по cookie; `web/errors.py` формирует ошибки полей.

Сценарии используют `db/` для соединений и начального наполнения базы, `core/security.py` для паролей и токенов, `services/` для повторно используемых операций с сессиями, JSON-контентом, представлением ответов, текстом и настройками. Эти модули не импортируют сценарии. Новый код сценария не должен попадать в общий модуль только ради увеличения числа папок.

Путь запроса при создании проекта:

```text
frontend/assets/js/pages/projects.js
  → POST /api/projects
  → features/projects.py: ProjectIn → create_project
  → db/connection.py → SQLite
  → services/serializers.py → JSON
```

## Добавить или изменить функцию

1. Найти файл сценария и изменить его модель входных данных и обработчик.
2. Если нужна новая самостоятельная функция, создать файл в `features/` и подключить его роутер в `web/routing.py`.
3. Вынести код в `services/`, только если он нужен нескольким сценариям.
4. Проверить существующие сценарии: из корня проекта `.venv\Scripts\python -m pytest backend/tests`.

Фронтенд использует ES-модули: общий `assets/js/main.js` загружает модуль страницы по `body[data-page]`. Все HTML-страницы находятся в `frontend/pages/`; общие стили и компоненты — в `frontend/assets/`. Данные демонстрации редактируются отдельно в `content/`.

Запуск: `uvicorn app.main:app --app-dir backend --reload`. Сайт и API обслуживает одно приложение.
