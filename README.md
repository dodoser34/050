# Среда — платформа для совместных проектов

Люди находят друг друга, собирают команды и запускают проекты.
Бэкенд — FastAPI + SQLite. Фронтенд — HTML, CSS и JavaScript на ES-модулях, без сборщика и фреймворков.

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate                       # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --app-dir backend --reload
```

- Сайт: http://localhost:8000
- Документация API: http://localhost:8000/api/docs

База `data/sreda.db` создаётся при первом запуске и заполняется демо-контентом из `content/`. Если поменять `version` в `content/taxonomy.json`, демо-контент пересоздастся; пользователи и их проекты при этом сохранятся.

### Демо-вход

На страницах `/login` и `/register` есть кнопка «Демо-вход — без регистрации». Можно и войти вручную: `demo@sreda.dev` / `demo-sreda-2026`.

Что уже есть в демо-аккаунте:
- свой проект «Зерно» (открывается в «Мои проекты»);
- лайки, избранные специалисты и отклик на проект.

Аккаунт пересоздаётся автоматически при старте (`backend/app/db/demo.py`). На боевом сервере демо-вход выключается так: `SREDA_DEMO=0`. Логин и пароль задаются через `SREDA_DEMO_EMAIL` и `SREDA_DEMO_PASSWORD`.

Тесты:

```bash
pip install -r requirements-dev.txt
python -m pytest backend/tests
```

Архитектура — **компактное приложение по сценариям**: изменение функции начинается с одного файла в `features/`. [Устройство и правила расширения](docs/ARCHITECTURE.md).

## GitHub Pages

Демоверсия: https://dodoser34.github.io/050/

Workflow `.github/workflows/pages.yml` собирает и публикует сайт при каждом push в `main`.
В настройках репозитория **Settings → Pages → Source** выберите **GitHub Actions**.

Локальная проверка статической версии:

```bash
python -m tools.build_pages --base-path /
python -m http.server 8080 --directory output/pages
```

Откройте http://localhost:8080/. Для публикации в проектном URL сборка получает
префикс репозитория (например, `--base-path /050/`) из настроек GitHub Pages.

Экспорт содержит только исходный демо-контент из `content/` и изображения. Локальная база
`data/sreda.db`, серверные аккаунты, пароли и пользовательские изменения в публикацию не попадают.

На GitHub Pages доступны демо-регистрация и вход. Под формами регистрации и входа расположен
блок «Попробовать без регистрации» с ролями «Пользователь» и «Администратор».
Повторно выбрать роль можно через пункт «Демо: сменить роль» в меню аккаунта.
Пользователь может заполнить анкету, создать и редактировать проект, поставить лайк, сохранить специалиста,
отправить отклик или приглашение, переписываться (демо-анкеты отвечают автоматически), вести блог и ленту проекта,
пожаловаться на материал. Логика сценариев для демо повторена в `tools/pages_social.js`. Администратор
проверяет материалы, указывает причину отклонения, выбирает героев главной и меняет роли.
В начальных данных уже есть анкета и проект на проверке.

Изменения и аккаунты сохраняются только в браузере (`localStorage`), без отправки на сервер
и без синхронизации с другими посетителями. Используйте вымышленные данные и отдельный пароль;
вместо введённого пароля сохраняется PBKDF2-хеш с индивидуальной солью. Очистка данных сайта
сбрасывает демо. Это демонстрация ролей, а настоящую авторизацию обеспечивает FastAPI.
Созданные в браузере проекты и анкеты открываются через `/projects/view/?slug=…`
и `/people/view/?slug=…`, поэтому работают после обновления страницы на статическом хостинге.

## Структура проекта

```
backend/
  app/
    main.py              создание приложения, подключение роутов и статики
    config.py            пути, cookie, сроки сессий (переменные окружения SREDA_*)
    features/            сценарии: auth, account, people, projects, home, search, admin
                         в каждом файле — HTTP-обработчики и их модели входных данных
    web/                 routing.py, pages.py, dependencies.py, errors.py
    core/security.py     bcrypt, токены сессий
    db/                  schema.sql, connection.py, seed.py, accounts.py, demo.py
    services/            общий код: контент, сериализация, сессии, настройки, текст
  tests/                 pytest: авторизация, каталоги, проект, страницы, статика
content/                 демо-контент в JSON: specialists (30), projects (20), taxonomy
frontend/
  pages/                 HTML-страницы: index, services, projects, project, profile, about, login, register
  assets/
    css/main.css         точка входа; base/ (токены, сетка), components/, pages/
    js/main.js           точка входа; core/ (api, сессия, иконки, заглушки), components/, pages/
    img/                 people/ · portfolio/ · projects/ · illustrations/ (генерируются по prompts/)
prompts/                 задания для 116 изображений, манифест и исходный макет Hero Motion
tools/                   build_prompts.py (собирает images.prompt из content/), image_assets.py (учёт и сохранение картинок)
```

## Страницы

| URL | Что там |
|---|---|
| `/` | Полноэкранный моушен-hero, бегущая строка, поиск, «Открытия недели», люди недели, цифры, «Как это работает», призыв создать проект |
| `/services` | Каталог специалистов и организаций: поиск, направления, формат, город, доступность. Фильтры сохраняются в адресе страницы; на телефоне открываются шторкой по кнопке «Фильтры» рядом с сортировкой |
| `/projects` | Каталог проектов: категории, стадия, роль, лицензия, «ищут участников», бета-версия, «Показать ещё» |
| `/projects/{slug}` | Страница проекта: этапы, открытые роли, отклик, команда, лента проекта (записи, результаты, опросы), автор, похожие проекты. Автору — редактирование, обложка, «завершён», удаление, команда и права участников, отклики с решениями |
| `/people/{slug}` | Профиль: портфолио (изображения, видео, проекты), блог, проекты (активные и завершённые, «Основатель» / «Участник»), опыт или сотрудники организации, отзывы, статус «в сети», жалоба |
| `/messages` | Сообщения: диалоги, переписка по откликам, принятие и отклонение откликов прямо в чате |
| `/me` | Кабинет: анкета, мои отклики, уведомления, сотрудники организации, настройки (тема, анимации, приватность) |
| `/about` | О платформе, живые цифры, ценности |
| `/login`, `/register` | Вход и регистрация |

Кликабельно всё: карточки проектов и специалистов, участники команд, авторы, работы портфолио, результаты поиска, вакансии.

## API

- `POST /api/auth/register | login | logout`, `GET /api/auth/me`
  - пароль хешируется через bcrypt;
  - почта проверяется через email-validator;
  - сессия хранится в HttpOnly-cookie, в базе лежит только SHA-256 токена.
- `GET /api/specialists`, `/api/specialists/meta`, `/api/specialists/{slug}`; `POST .../bookmark`, `POST .../invite`
- `GET /api/projects`, `/api/projects/meta`, `/api/projects/{slug}`; `POST /api/projects`, `POST .../{slug}/apply`, `POST .../{id}/like`
- `PUT|DELETE /api/projects/{slug}`, `PUT /api/projects/{slug}/team`, `GET /api/projects/{slug}/applications`, `POST /api/applications/{id}/decision`
- `GET|POST /api/conversations`, `GET /api/conversations/{id}?after=`, `POST /api/conversations/{id}/messages` — сообщения
- `GET /api/notifications`, `POST /api/notifications/read`, `GET /api/me/summary` — уведомления и счётчики
- `GET|POST /api/posts`, `DELETE /api/posts/{id}`, `POST /api/posts/{id}/vote` — блоги, лента проекта, опросы
- `POST /api/reports`, `GET|POST /api/admin/reports…` — жалобы и их разбор
- `GET|PUT /api/me/settings`, `GET|PUT /api/me/org`, `GET /api/me/applications` — приватность, сотрудники, мои отклики
- `GET /api/search?q=` — общий поиск по людям, организациям и проектам.

Загруженные картинки (обложки, портфолио, аватары, картинки постов) браузер сжимает перед отправкой,
сервер сохраняет их в `data/uploads/` (`SREDA_UPLOADS_DIR`) и отдаёт по адресу `/uploads/…`.

## Hero главной

Это векторная анимация, перенесённая один в один из композиции Claude Design («Среда — Hero Motion»). Код — в `frontend/assets/js/pages/hero-motion.js`. Последовательность:

1. Орбиты прорисовываются и переливаются.
2. Дуга собирается из двух половин.
3. Сверху падает шар, дважды отскакивает, по поверхности расходятся волны.
4. По нейронам бегут искры.
5. Появляются участники проекта «Пульс» с подписями ролей.

После этого крутится 6-секундный «живой» цикл.

- Время анимации идёт по реальным часам: при редких кадрах она не тормозит.
- Когда hero уходит с экрана или вкладка скрыта, анимация встаёт на паузу.
- Клик мышью по сцене проигрывает её заново (на телефоне отключено: случайное касание при прокрутке перезапускало анимацию).
- Текст hero появляется через CSS и виден, даже если скрипты ещё грузятся.
- Параметр `?hero-t=8` открывает страницу сразу на нужной секунде.
- Настройка «Анимации» и системная `prefers-reduced-motion` учитываются: без анимаций сразу рисуется готовый кадр.

## Адаптив и анимации

- Сетка широкая, до 1920px. Карточки раскладываются автоматически: от 1 колонки на телефоне до 5–6 на больших экранах.
- Все размеры заданы в `rem`, корневой шрифт растёт на 2K, 3K, 4K и 5K (`base/tokens.css`), поэтому на больших мониторах интерфейс не мельчит.
- Тема: светлая, тёмная или как в системе; анимации: «Все», «Спокойные» (по умолчанию — только короткое проявление блоков) или «Выключены».
  Переключатели — в мобильном меню и в кабинете → «Настройки», хранятся в браузере (`core/prefs.js`, ставятся до отрисовки в `assets/js/boot.js`).
- Анимации:
  - появление при прокрутке, заголовки «по словам» (только режим «Все»), счётчики;
  - статичные декоративные иллюстрации с мягкими краями; моушен-сцена на первом экране главной;
  - ховеры карточек, блик на кнопках, бегущая строка;
  - плавные переходы между страницами (View Transitions).

## Изображения

Список всех картинок — в `prompts/images.prompt`. Пока файла нет, сайт показывает векторную заглушку (`core/placeholders.js`), поэтому картинки можно добавлять постепенно.

Тёмные версии иллюстраций для тёмной темы — в `prompts/images-dark.prompt` (файлы `illustrations/*-dark.webp`).
Сайт сам подставляет их в тёмной теме; пока файла нет, показывает приглушённую светлую версию.

```bash
python -m tools.build_prompts          # пересобрать промпты (images.prompt и images-dark.prompt) после правок content/
python -m tools.image_assets status    # сколько картинок готово
```
